# Ассемблер и симулятор 8051 для автопроверки программ (КМ-3)

Ресерч 2026-09-30 (сабагент, практическая проверка в песочнице). Цель — собирать и гонять три программы в синтаксисе робота
(Keil A51 / Intel ASM51, шаблон — ТЗ-2026 с. 9, рис. 7) локально (macOS) и в CI (Ubuntu 24.04).
Тест-файл: шаблон рис. 7 + `$INCLUDE (vars.inc)`, DSEG AT/DS, CSEG AT, org-заглушки, `call …; %proc%`, `jmp $; %stop%`, BIT, movx, цикл, DB, END.

## Ассемблеры

| Кандидат | Лицензия / активность | DSEG/CSEG AT, BIT, generic call/jmp | Include | Итог |
|---|---|---|---|---|
| **MCU 8051 IDE 1.4.9** (apt `mcu8051ide`) | GPL-2, Tcl, ~2018 | всё есть; `mcu8051ide -n --compile f.a51` headless, ошибка → rc=1 | `$INCLUDE (f)` и `include f` | ✅ Docker ubuntu:24.04; образ **побайтно = ASEM-51** |
| **ASEM-51 1.3** (plit.de/asem-51) | freeware, закрытый, распространять без изменений; 2002 | всё есть; generic: вперёд → LJMP/LCALL, назад → короткий | только `$INCLUDE (f)` | ✅ HEX; бинарник i386 ELF — на macOS только через qemu в Docker; на x86_64 Ubuntu нативно **не проверено** |
| cpen312-a51 | GPL-2 | ❌ баг `CSEG AT 0h` после DSEG | — | нет |
| asm51 (wojtekka) | GPL-2 | ❌ нет DSEG | — | нет |
| naken_asm | GPL-3 | ❌ нет DSEG, `$INCLUDE` | — | нет |
| sdas8051 (sdcc) | GPL-3 | ❌ синтаксис asxxxx | — | нет |
| as31 | — | `.org`/`.equ`, без DSEG | — | нет (по документации) |
| Keil A51 | коммерческий, Windows | эталон робота | `$INCLUDE` | в CI нельзя |

Что всплыло на старых программах из `docs/prev` (4 файла): UTF-8 BOM ломает ASEM («illegal character»); SFR AT89S53 (WDTRST, T2, SPI) —
нужен `$INCLUDE (89S53.MCU)` (ASEM) — в MIDE `setb WDTRST` не проходит; `DW a,b,c` не понимает MIDE; метка с пробелом перед «:» не понимает MIDE;
`mov r7,R0` — невалидна (ловят оба).

**Для сдачи:** робот принимает один `.txt` — `$INCLUDE` в сданном файле не сработает. Генератор должен **вклеивать `vars.inc`** в текст программы и **снимать BOM**.

## Симуляторы

| Кандидат | Лицензия | CLI/скрипты | Хуки XRAM (movx) | INT0/1 | Такты |
|---|---|---|---|---|---|
| **ucsim / s51** (sdcc 4.6.0; brew `sdcc`) | GPL-2, C++, активен | команды со stdin (`s51 -q -t 8052 -X 12M f.hex < script`), TCP `-Z`, `-P` — разделитель для управляющей программы | ✅ `break xram w 0x2000` — останов после записи, контроллер читает/пишет `xram[…]`, `run`; `break sfr w 0x90` — фронты P1 | ✅ `set hardware port[3] 0xfb` (P3.2 в 0) → вектор 03h | ✅ `state` («Total time … clks»), `step N us/ms/clk` |
| emu8051 (jarikomppa, MIT) | C, ~3 тыс. строк | библиотека | ✅ колбэки `xread/xwrite/sfrwrite` | ⚠ IE0 вручную | ❌ **баг таймингов**: 2-цикловые за 1 (27 МЦ вместо 43) |
| MCU 8051 IDE simulator | GPL-2 | только GUI | — | — | — |
| go51, py 8051-Simulator, js51, mcs51-emulator (Rust) | мелкие/заброшенные/без лицензии | — | — | — | не брать |

Практика ucsim 0.9.9 (macOS) на HEX от ASEM: останов на записи в xram[0x2000] (клавиатура), подстановка строк 0xF7 → прочитано программой;
копия XRAM A000..A002 в IRAM; запись Y2 в xram[0xC000]; фронты PIN_Y1 по `break sfr w 0x90`: 516 clks = 43 МЦ = 43 мкс (совпало с ручным пересчётом);
INT0 через пин — 2 срабатывания.
Нюансы: IRAM после старта случайная (ловит неинициализированные переменные; детерминизм — `-R seed`); **apt Ubuntu 24.04 — ucsim 0.6.4** с другими тактами → фиксировать одну версию (sdcc 4.6.0) и локально, и в CI.

## Запасной вариант — свои ассемблер и эмулятор на Go

Ассемблер подмножества A51 ≈ 1–1,5 тыс. строк (2 прохода, 255 опкодов, DSEG/CSEG/BSEG/XSEG AT, ORG, EQU, SET, BIT, DS, DB, DW, END, include, generic JMP/CALL по правилу ASEM),
проверка — побайтно с MIDE/ASEM. Эмулятор ≈ 1,5–2 тыс. строк (опкоды, флаги DA/AC/OV, таймеры, прерывания, счёт МЦ, шина `Read/Write(addr)` на Go),
проверка — трассы против ucsim. Риски: флаги, задержка входа в прерывание, длина generic jmp у Keil (допуск в тестах длительностей).

## Рекомендация

1. **Ассемблер:** MCU 8051 IDE (CI: `apt-get install -y --no-install-recommends mcu8051ide`; macOS — Docker ubuntu:24.04). ASEM-51 — второе мнение в CI (в репо не класть — лицензия).
2. **Симулятор:** ucsim (s51) из sdcc 4.6.0 (macOS — `brew install sdcc`; CI — тот же brew на ubuntu-раннере или сборка из исходников; предустановленность brew на раннере **не проверена**; apt-версию не брать).
3. **Тесты:** Go-обвязка `internal/sim51` над `s51 -q -P -t 8052 -X 12M prog.hex` (stdin/stdout): `break xram w ADR` на адресах устройств → Go-модели
   (клавиатура: столбцы → строки; IDT7005 — XRAM; Y2/индикатор — лог записей с тактом), `break sfr w 0x90/0xB0` + `state` — длительности стробов,
   `set hardware port[3]` — «нажатие» (INT0) и строб X2 (INT1); проверки — `iram[…]`, `xram[…]`, `sfr[…]`, биты; адреса — из `vars.inc`.
4. **Дописать:** клиент протокола s51, модели устройств, прекомпилятор (BOM, вклейка `vars.inc`, линтер `%proc%`/`%stop%`, длины комментариев ≤ 250 и имён ≤ 60),
   EQU для SFR AT89S53, регрессия на программах из `docs/prev`. Если обвязка над ucsim хрупкая — свой эмулятор на Go, ucsim как эталон.
