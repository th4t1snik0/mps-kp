# Пояснительные записки: что генерируется, что дописывает студент (гайд для людей и ИИ)

Работа сдаётся по контрольным мероприятиям, у каждого — своя джоба в GitHub Actions:

| КМ | Что сдаётся | Джоба | Что делает джоба |
| --- | --- | --- | --- |
| КМ-1 | схема Э3 (PNG) + черновик перечня (микросхемы, разъёмы) | **КМ-1 схема и перечень** (`km1.yml`) | схема по варианту, ERC, перечни ПЭ3 |
| КМ-2 | ПЗ1 — аппаратная часть | **КМ-2 ПЗ1** (`km2.yml`) | схема + ПЗ1 в docx: структурная и функциональная схемы, фрагменты Э3 по узлам, расчёты из перечня, таблицы, временные диаграммы, перечень, Э3 |
| КМ-3 | ПЗ2 — программная часть + три программы | **КМ-3 программы и ПЗ2** (`km3.yml`) | проверка программ, файлы для робота, ПЗ2 в docx |
| КМ-4 | защита | — | банк вопросов — `docs/research/remarks-and-defense.md` |

Результаты — ветка `results` → `<группа>-23/<M>/прогон-N/` (папки `pz1/`, `code/`, `pz2/`) и Яндекс-диск. Каждый прогон — новая папка.

## Принцип

Документ = **генерируемое** (таблицы, расчёты, рисунки, листинги — всё, что можно посчитать или нарисовать точно) +
**текст студента** в `students/<ник>/pz/pzN.md` по местам «ДОПИШИ». Генерируемое пересобирается при каждом прогоне
(поменялся код — поменялись таблица подпрограмм, листинги, глубина стека), текст студента не перетирается.
Незаполненное место в docx — жёлтый абзац «✍ ДОПИШИ (ид …)»; список незаполненных — в `report.md` рядом с docx.
PDF студент делает сам (Word/LibreOffice → «Сохранить как PDF»), когда допишет и проверит.

**Вид документа** — по образцам принятых работ, у группы не одинаковый (выбирается от ФИО; задать явно — `pz_style: A|B|C` в `students/<ник>/variant.yaml`):
A — как Осипова 2025 (номер и «Курсовая работа, МПС ч2» сверху, заголовки прописными по центру, «Рис. 3.1.»),
B — как Базарнов 2023 / Женюх 2022 («Приложение Б» на титуле, номер снизу, «Рис. N.»), C — ГОСТ 7.32 («Рисунок N —», «Таблица N —»).
Титул — по шаблону Прил. Б (боковые графы, «Листов N» — поле, Word посчитает). Содержание — поле Word: при открытии Word спросит
«обновить поля?» — да, появятся номера страниц. **Блок-схемы** рисуются одним из 5 шрифтов и с разными пропорциями — тоже от ФИО.
Посмотреть все три вида постранично — Actions → «ПЗ превью» → Run workflow (ник, pz2) → артефакт `preview`.

## ПЗ1 (КМ-2): рецепт для ИИ

1. Нужен только `students/<ник>/variant.yaml`: схему, перечень и всё считаемое джоба КМ-2 строит сама (KiCad в CI).
2. `make pz1-init S=<ник>` (или создать руками по образцу ниже) → `students/<ник>/pz/pz1.md` — три места «ДОПИШИ»:
   введение своими словами, механизм обмена через буфер, сравнение времён IDT7005 с таблицей параметров шины МК
   (цифры IDT7005 — из даташита исполнения S55, в репо его нет: не выдумывай, возьми из PDF производителя).
3. Push → Actions «КМ-2 ПЗ1» → `results/…/прогон-N/pz1/«Фамилия ИО ПЗ1.docx»`. Локально: `make pz1 S=<ник>` (нужны KiCad и pandoc).

Что генерируется (порядок — как у принятой ПЗ1 Осиповой 2025 + требования ТЗ-2026 п. 2.1; выжимка — `docs/research/pz1-structure.md`):
титул по Прил. А ТЗ; содержание; введение; 1.1 структурная (рис. 2 ТЗ) и функциональная схемы, распределение ресурсов;
1.2 МК-устройство (фрагмент Э3, кварц, RC-сброс с расчётом τ, защёлка, **дешифратор** и таблица «Yn → устройство», таблица 40 выводов МК,
карта адресов); 1.3 клавиатура (фрагмент, расчёт RC антидребезга и тока кнопки, коды клавиш) и индикатор (фрагмент, расчёт резистора
сегмента, коды символов ОК/ОА); 1.4 буфер (фрагмент, разрядность адреса, временные диаграммы чтения и записи с параметрами AT89S53);
1.5 интерфейсные устройства (Y1, Y2, нагрузка портов); 1.6 помехоустойчивость (33 нФ на корпус, 470 мкФ); литература;
Прил. А — перечень элементов (ГОСТ 2.701), Прил. Б — схема Э3. Все номиналы и обозначения — из того же перечня, что и схема
(замечание руководителя: «номиналы на схеме = в перечне = в расчётах»).

## ПЗ2 (КМ-3): рецепт для ИИ

1. Программы уже проходят `make code S=<ник>` (см. `docs/code-guide.md`) — ПЗ2 описывает именно их.
2. `make pz2-init S=<ник>` → `students/<ник>/pz/pz2.md` (места «ДОПИШИ» с подсказками) и заготовки схем алгоритмов
   `students/<ник>/pz/flow/*.flow` под вариант (если папка пуста). Повторный запуск безопасен: текст сохраняется, порядок
   разделов — как в документе, разделы, которых больше нет, уходят в конец с пометкой «НЕ ИСПОЛЬЗУЕТСЯ».
3. **Схемы алгоритмов** — ТЗ (разд. 2.2) требует алгоритмы **всех** узлов, не только трёх программ: заготовки `01-init` … `12-t1`
   (основной цикл, клавиатура и реакция на клавиши, буфер — запись, чтение, очистка, индикатор, Timer0, Y1, Y2, Timer1).
   Те, что реализованы в твоём коде, подгони под **свой** код (схема обязана соответствовать программе). Имя файла задаёт порядок.
   Пояснение к каждой схеме генератор пишет сам (пересказ схемы по шагам); свой текст — в `pz2.md`, раздел `flow.<имя>`.
4. **Текст** — пиши под подсказками в `pz2.md`. Коротко и по делу, своими словами, со ссылками на рисунки и таблицы
   («рисунок 2», «таблица 1» — номера видны в docx). Не переписывай то, что уже сгенерировано.
5. `make pz2 S=<ник>` → `build/<группа>-23/<M>/pz2/«Фамилия ИО ПЗ2.docx»` (нужен pandoc: `brew install pandoc`).
   Открой, при открытии Word обновит оглавление. Смотри `report.md`: сколько мест осталось.
6. Коммить `students/<ник>/pz/pz2.md` и `flow/*.flow`; джоба КМ-3 соберёт ПЗ2 и выложит в `results`.

Что генерируется в ПЗ2 (шаблон Прил. Б ТЗ): титул, аннотация, содержание, разд. 1–2 (с числами варианта), таблица подпрограмм
**из комментариев в коде** (имя, назначение, «Вход:», «Выход:», «Портит:» — пиши их в заголовке каждой процедуры),
прерывания, адреса устройств, переменные ОЗУ (из `vars.inc` и DSEG программ), клавиатура и коды клавиш, коды сегментов
(ОК/ОА), коды ошибок (заготовка), время заполнения буфера, **глубина стека — измерена в эмуляторе** на сценариях проверки,
сокращения, листинги трёх программ в приложении.

## Формат схем алгоритмов (`*.flow`)

Строки с отступом по 2 пробела; джоба рисует по ГОСТ 19.701 (символы, «да/нет», границы цикла, перенос в колонки через соединители).

```text
# Подпрограмма записи в кольцевой буфер BufPut      ← подпись рисунка
начало: BufPut (A — отсчёт)                          ← терминатор
действие: B := A                                     ← процесс
если: Буфер полон?                                   ← решение
  да:
    вызов: BufNext: хвост := следующая ячейка        ← предопределённый процесс (вызов подпрограммы)
    действие: Флаг переполнения := 1
  нет:                                               ← ветку «нет» можно не писать
данные: Записать B в ячейку «головы»                 ← ввод-вывод (movx, порты)
цикл: Ц1: для столбцов 1…3                           ← граница цикла; тело — с отступом
  действие: …
конец: Возврат                                        ← терминатор
```

Текст в символе переносится сам; `\n` — принудительный перенос. Обратных стрелок нет: повторение — только циклом.
Проверить одну схему быстро: `make pz2 S=<ник>` и открыть `build/…/pz2/flow-<имя>.png`.
