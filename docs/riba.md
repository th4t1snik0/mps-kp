# Пошагово с нуля

## Устройство на пальцах

Ты проектируешь маленький пульт: человек жмёт цифру, внешняя железка присылает числа, пульт их складывает и отдаёт результат наружу. Всё остальное — детали того, как это собрать и описать.

Термины, без которых дальше не прочитать:

- **МК AT89S53** — микроконтроллер семейства 8051: процессор, 256 байт ОЗУ, память программ, 2 таймера, 2 внешних прерывания, 4 порта по 8 ножек.
- **Шина** — общие провода, по которым МК обращается к внешним микросхемам: P0 (младший байт адреса, затем данные), P2 (старший байт адреса), P3.6 = WR, P3.7 = RD, ALE.
- **Адрес** — 16-битное число, которое МК выставляет на шину командой `movx`. Какие биты адреса = 0, определяет, какая микросхема ответит.
- **CS (Chip Select)** — вход «выбора» микросхемы, активен нулём. У тебя это ножки P2.3–P2.7, по одной на устройство.
- **RD / WR** — стробы чтения/записи МК. `movx A,@DPTR` даёт импульс RD, `movx @DPTR,A` — импульс WR.
- **Регистр-защёлка (573)** — 8 триггеров: по сигналу Load запоминает байт с шины и держит его на выходах, пока не запишут новый.
- **Регистр 173** — то же, но 4 бита; у тебя держит состояние столбцов клавиатуры.
- **Буфер с тремя состояниями (244)** — выдаёт свои входы на шину только когда его выбрали, в остальное время его выходы отключены.
- **Двухпортовое ОЗУ IDT7005** — память с двумя независимыми наборами адреса/данных/управления: левый порт подключён к МК, правый — к внешнему устройству.
- **Прерывание INT0/INT1** — спад на ножке P3.2/P3.3 заставляет МК прервать текущую программу и выполнить обработчик по фиксированному адресу (03h / 13h).
- **Таймер** — 16-битный счётчик машинных циклов (1 мкс при 12 МГц); при переполнении вызывает прерывание (0Bh / 1Bh).

Что подключено к начальнику:

| Устройство | Зачем | Как с ним говорят |
| --- | --- | --- |
| Клавиатура 12 кнопок | человек вводит цифру X1, «Тест», «Сброс» | пишем столбцы в регистр, читаем строки через повторитель; нажатие = звонок INT |
| Индикатор, 1 цифра | показать нажатую цифру или ошибку | пишем код сегментов в регистр |
| Кольцевой буфер (IDT7005) | копить числа X2 от внешнего устройства | оно звонит в INT, мы кладём число в ящик; потом достаём по одному |
| Регистр Y2 | выдать результат наружу | пишем Y2, дёргаем строб на P1 |
| Ножка Y1 на P1 | строб по кнопке «Тест» | просто 0 на время T1, потом 1 |

Весь смысл работы в одну строку: Y2 = (M + X1 + X2) mod 256, пока X1 ≠ 0 и в буфере есть X2.

Всё общение МК с устройствами идёт по шине с разными адресами; только стробы Y1/Y2 идут напрямую с ножек P1, а кнопки и X2 сами «звонят» в МК через INT.

## Шаг 1. Посчитать свой вариант (30 минут)

На выходе — одна табличка со всеми твоими числами. Она нужна на каждом следующем шаге, поэтому делаешь её первой и держишь открытой. Справа — пример для А-12, M = 14.

| # | Что делаешь | Где взять | Пример |
| --- | --- | --- | --- |
| 1.1 | Узнай свою группу и номер M в БАРС | БАРС | А-12, M = 14 |
| 1.2 | Посчитай k = M mod 7 (остаток от деления) | — | 14 mod 7 = 0 |
| 1.3 | Строб Y1 — ножка P1.k, строб Y2 — P1.(k+1) | — | P1.0 и P1.1 |
| 1.4 | Посчитай T1, V, T2, T3 по формулам своей группы | «Параметры варианта» | 352 мс, 1540 байт, 1745 мкс, 2,830 с |
| 1.5 | Выпиши, какой таймер на Y1, какой на Y2 | там же | Y1 и T3 — Timer1, Y2 — Timer0 |
| 1.6 | Выпиши CS-ножки: буфер, регистр Y2, индикатор (по чётности M), клавиатура | там же | P2.5, P2.4, P2.7, P2.6 |
| 1.7 | Выпиши, на каком INT клавиатура; X2 — на другом | там же | клава INT0, X2 → INT1 |
| 1.8 | Адреса «головы»/«хвоста» и номера битов флагов | там же | 42h/44h; биты 26 и 14 |
| 1.9 | Чётность M → размер клавиатуры и программа 2 | «Три программы» | чётное: 4×3, чтение буфера |
| 1.10 | M mod 3 → программа 3 | там же | 14 mod 3 = 2 → Y2 со стробом |
| 1.11 | Тип индикатора (общий катод/анод) по своей группе | табл. 1 ТЗ | общий катод, FYS-5612AX |

Проверка себя: у тебя должно получиться 4 разные CS-ножки из P2.3–P2.7 (одна лишняя), два разных INT и два разных таймера.

## Шаг 2. Раздать ресурсы МК (1 час)

На выходе — таблица «ножка/таймер/адрес → кому принадлежит». Это одновременно раздел функциональной схемы в ПЗ1 и раздел 3.2 в ПЗ2, так что пишется один раз.

1. Выпиши все ножки МК, которые используешь:
   - P0 — младшие 8 бит адреса, потом данные (мультиплексированы).
   - P2.0–P2.2 — старшие биты адреса для буфера (A8–A10).
   - P2.3–P2.7 — CS устройств из шага 1.6.
   - P3.2 / P3.3 — INT0 / INT1 из шага 1.7.
   - P3.6 / P3.7 — WR / RD.
   - ALE — строб защёлки адреса.
   - P1.k, P1.(k+1) — стробы Y1, Y2.
2. Посчитай адрес каждого устройства: возьми F8h, поставь 0 в бит его CS — получишь старший байт, младший = 00h. Таблица готовых вариантов — в «Производных параметрах».
3. Составь карту памяти: окна по 2 Кбайт на каждое устройство, всё остальное «не используется».
4. Раздай таймеры: Y1 и T3 — один (они не пересекаются: во время «Теста» индикатор погашен), Y2 — второй.
5. Раздай прерывания и приоритеты: X2 — высокий приоритет (так требует ТЗ), клавиатура и таймеры — низкий.
6. Раздай внутреннюю память: «голова» и «хвост» по заданным адресам (по 2 байта), флаги по заданным битам, X1, X2, счётчики таймеров — где-нибудь от 30h, не пересекаясь с «головой»/«хвостом».

Проверка себя: ни одна ножка, адрес или байт ОЗУ не встречается в таблице дважды.

## Шаг 3. Нарисовать схему Э3 в KiCad (КМ-1)

Схему рисуют в KiCad 9 с ГОСТ-библиотекой и ГОСТ-рамкой из папки группы. Visio из той же папки нужен не для схемы, а для блок-схем алгоритмов в ПЗ2 (трафарет по ГОСТ 19.003-80).

### 3.1. Подготовка (20 минут)

1. Скачай и установи KiCad 9 с kicad.org. Рамка в папке группы сделана в 9.0, в более старой версии она может не открыться.
2. Из папки группы «КП по микропроцессорным системам» скачай целиком папку `kicad-gost-library-master` и файл `gost_ramka.kicad_wks`.
3. Там же открой чужие схемы (`МПС КР Принц *.png/jpg`) — это образцы того, как лист должен выглядеть в итоге.
4. Запусти KiCad → «Файл → Новый проект» → имя, например `MPS_var14`. Появятся два файла: `.kicad_pro` (проект) и `.kicad_sch` (схема).
5. Положи `gost_ramka.kicad_wks` и папку библиотеки рядом с проектом, чтобы проект не зависел от путей на другом компьютере.

### 3.2. Подключить ГОСТ-библиотеку

1. В окне проекта: «Настройки → Управление библиотеками символов» → вкладка «Библиотеки проекта».
2. Кнопкой «Добавить существующую» выбери файлы `.lib` из `kicad-gost-library-master`. Нужны: `Device_GOST` (резисторы, конденсаторы, кварц, кнопки), `Diode_GOST`, `power_GOST` (+5V, GND), `Connector_Generic_GOST` (разъёмы), `Logic_CMOS_1564_GOST` (логика).
3. Если KiCad предложит перевести библиотеки в новый формат — соглашайся.
4. Микросхем AT89S53, IDT7005, 74xx573/173/244 и индикатора FYS в этой библиотеке нет. Их или ищешь в стандартных библиотеках KiCad поиском по номеру («573», «244», «173»), или рисуешь сам по шагу 3.4.

### 3.3. Рамка А3 и основная надпись

1. Открой схему (двойной клик по `.kicad_sch`).
2. «Файл → Параметры страницы»: размер **A3**, ориентация **альбомная**.
3. Там же в поле «Файл оформления листа» выбери `gost_ramka.kicad_wks`.
4. Заполни «Дату» и «Комментарии» 2 и 3 — они выводятся в рамке через поля `${COMMENT2}`, `${COMMENT3}`, `${ISSUE_DATE}`. Проверь по превью, в какой строке (Разраб. / Пров.) оказывается каждый.
5. В рамке жёстко вписано «Группа А-12-22, Вариант 12, Э3». Чтобы поменять: в окне проекта открой «Редактор оформления листа», открой `gost_ramka.kicad_wks`, дважды кликни по этой надписи, исправь группу и вариант, сохрани.

### 3.4. Нарисовать недостающие микросхемы

По ГОСТ 2.743 микросхема — это прямоугольник: названия выводов внутри, номера снаружи, сверху позиционное обозначение (DD3) и тип (AT89S53). Твоя текущая схема нарисована именно так.

1. В окне проекта: «Редактор символов» → «Файл → Новая библиотека» → «Проект» → имя `MPS_my`.
2. «Файл → Новый символ» → имя `AT89S53`, обозначение по умолчанию `DD`.
3. Нарисуй прямоугольник (инструмент «Прямоугольник»).
4. Добавь вывод: клавиша **P** → номер (1), имя (P1.0), тип (двунаправленный / вход / выход / питание) → поставь на левую или правую сторону прямоугольника. Шаг выводов — 100 mil, длина 200 mil (так в README библиотеки).
5. Для следующих выводов жми **Insert**: KiCad повторит последний вывод со сдвигом и увеличит номер на 1. Имя поправишь двойным кликом.
6. Выводы ставь по таблице из даташита (номер → имя). Питание (40 VCC, 20 GND) тоже рисуй — на схеме они подключаются явно.
7. Сохрани и повтори для IDT7005 (по даташиту, 68 выводов), 74xx573 (20 выводов), 74xx173 (16), 74xx244 (20), FYS-5612 (10).
8. Вернись в «Управление библиотеками символов» и проверь, что `MPS_my` появилась в библиотеках проекта.

### 3.5. Расставить элементы

Горячие клавиши в редакторе схемы: **A** — поставить символ, **P** — питание (+5V, GND), **R** — повернуть, **M** — передвинуть, **E** — свойства, **W** — провод, **B** — шина, **L** — метка цепи, **Q** — «не подключено».

1. **A** → AT89S53 → поставь в левую верхнюю часть листа. Раскладку листа бери из Приложения А методички.
2. Справа от МК поставь защёлку адреса (573), правее — IDT7005.
3. Снизу — клавиатурный узел (173, 244, кнопки, диоды, резисторы, конденсаторы), справа снизу — регистр индикатора и индикатор.
4. Регистр Y2 — рядом с разъёмами выходных сигналов.
5. Разъёмы (питание, вход X2, выходы Y) — у правого края листа.
6. Цепь питания (470 мкФ и ряд по 68 нФ) — внизу слева.
7. Кварц и два конденсатора по 30 пФ — вплотную к XTAL1/XTAL2 МК.

### 3.6. Соединить

1. Короткие связи рисуй проводами (**W**): кварц, RST, питание, связи внутри клавиатурного узла.
2. Длинные группы проводов (AD0–AD7, A0–A10) — шиной (**B**): жирная линия через лист.
3. От каждого вывода к шине — отвод («Разместить → Отвод от провода к шине») и метка (**L**) с именем проводника, например `AD3`. Одинаковые имена меток = один и тот же провод, даже если линии не соединены.
4. На саму шину поставь метку вида `AD[0..7]` — так KiCad поймёт, какие провода в ней.
5. Сигналы, которые идут далеко (CS\_buf, CS\_kb, RD, WR, INT0, ALE), тоже подписывай метками, а не тяни проводом через весь лист.
6. Питание подключай символами **P** → `+5V` и `GND` прямо у выводов.
7. На каждый неиспользуемый вывод микросхемы ставь **Q** («не подключено») или подключи его к GND/+5V, как требует даташит (входы логики в воздухе оставлять нельзя).

### 3.7. Номера, номиналы, проверка

1. «Инструменты → Аннотировать схему» → сортировка «слева направо, сверху вниз» → KiCad сам проставит DD1, R1, C1…
2. Каждому элементу нажми **E** и впиши номинал: `10k`, `330`, `220n`, `68n` (не 68p!), `30p`, `470u`.
3. «Проверка → Проверка электрических правил (ERC)». Каждую ошибку исправь: неподключённый вывод → провод или **Q**; конфликт выходов → проверь, не соединены ли два выхода.
4. Сверь схему с таблицей ресурсов из шага 2: каждая ножка МК подключена туда, куда записано.
5. Добавь на лист текстом «Примечание»: к каким ножкам подключены питание и неиспользуемые входы вентилей.

### 3.8. Сдать

1. «Файл → Печать/Вывод на плоттер» → формат **PDF** → вывести.
2. PDF в PNG переведи в 300 dpi (например, GIMP или любой онлайн-конвертер). JPG нельзя — ТЗ запрещает форматы с потерями.
3. Перечень элементов: шаблон `МПС КР Перечень элементов.doc` в папке группы. Для КМ-1 только микросхемы и разъёмы, в ПЗ1 — полный.
4. Отправь письмом с темой «МПС-Схема», файл «Фамилия ИО Схема-v1.png».

Проверка себя: ERC без ошибок; у каждой микросхемы подключены питание, CS, RD или WR и шина данных; логика — серии 1554/74HC/74AC; рамка заполнена, вариант твой.

## Шаг 4. Написать ПЗ1 (КМ-2)

ПЗ1 — это схема из шага 3, рассказанная словами, плюс расчёты. Пишешь по порядку блоков схемы: каждому блоку — кусок схемы, абзац «как подключено и зачем» и расчёт, если в блоке есть резисторы или конденсаторы.

1. **Титульник** — по Приложению А ТЗ.
2. **ТЗ** — переписать своими числами из шага 1.
3. **Структурная схема** — картинка из ТЗ + по строчке на блок (MPM, RAM, ROM, IOU, CPAN, IC).
4. **Функциональная схема** — МК, буфер, пульт; таблица ресурсов из шага 2.
5. **Шина** — схема защёлки, временная диаграмма чтения/записи МК, тайминги из даташита AT89S53.
6. **Кварц и сброс** — номиналы по даташиту (30 пФ, 10 кОм).
7. **Буфер** — как подключены оба порта и **как внешнее устройство в него пишет**: выставило X2 → дёрнуло строб → INT → МК записал → двигает «голову».
8. **Временная диаграмма МК ↔ буфер** — тайминги МК рядом со временем доступа IDT7005; вывод: «память быстрее, ожидания не нужны».
9. **Регистр Y2** — как формируется Load, где строб.
10. **Индикатор** — расчёт резистора: R ≥ (Vcc − U\_сегм − U\_вых) / I\_сегм, взять ближайший из ряда E24; таблица кодов цифр.
11. **Клавиатура** — схема одной кнопки, расчёт RC: 3·R·C ≥ 5 мс, ток через кнопку; таблица «столбец/строка → клавиша».
12. **Питание** — конденсаторы 470 мкФ и 68 нФ.
13. **Карта памяти** — таблица из шага 2.
14. **Оценка мощности** — сложить токи всех микросхем из даташитов + индикатор (8 сегментов × ток) + кнопки; P = Vcc · I\_сумм; вывод: «нужен источник 5 В, не меньше X мА».
15. **Литература** — даташиты со ссылками.
16. **Приложения** — перечень элементов, схема А3, выдержки из даташитов.

Проверка себя: каждый элемент со схемы упомянут в тексте; у каждого резистора и конденсатора есть формула → числа → выбранный номинал с маркой.

## Шаг 5. Придумать алгоритмы (самый важный шаг)

Программа тут — не «сверху вниз», а набор реакций на звонки. Поэтому сначала выписываешь, кто может позвонить, потом что делать на каждый звонок, и только потом рисуешь блок-схемы.

1. **Выпиши события.** Их ровно пять:

   | Событие | Кто звонит | Что должно случиться |
   | --- | --- | --- |
   | Нажата кнопка | INT клавиатуры | узнать какая → цифра / «Тест» / «Сброс» |
   | Пришло число X2 | INT буфера | положить в ящик, сдвинуть «голову» |
   | Кончился строб Y2 | таймер Y2 | поднять ножку строба в 1 |
   | Тикнул таймер Y1/T3 | таймер Y1/T3 | досчитать: погасить индикатор или закончить Y1 |
   | Ничего не происходит | — | главный цикл: есть данные и X1 ≠ 0 → выдать Y2 |
2. **Выпиши переменные**: X1, «голова», «хвост», 2 флага буфера, счётчик тиков, режим таймера (индикация или Y1), флаг «идёт строб Y2».
3. **Инициализация**: для каждой переменной и каждой ножки — начальное значение (все стробы = 1, индикатор погашен, X1 = 0, буфер пуст).
4. **Для каждого события** распиши шаги словами, 4–8 штук. Готовые версии — в «Алгоритмах подпрограмм» справочника.
5. **Главный цикл**: бесконечно проверяй «X1 ≠ 0 и буфер не пуст и строб не идёт» → достать X2 → посчитать Y2 → записать → строб.
6. **Подумай про столкновения**: что если X2 пришло, пока главный цикл читает буфер? → на время чтения запрети INT буфера. Что если «Тест» нажат во время индикации? → индикатор гасим, таймер отдаём Y1.
7. **Придумай 3–4 ошибки** для индикатора (готовая табличка — в справочнике).
8. **Нарисуй блок-схемы** по ГОСТ 19.701: овал — начало/конец, прямоугольник — действие, ромб — условие, прямоугольник с двойными боковыми линиями — вызов подпрограммы. Одна схема на событие + главный цикл + инициализация.

Проверка себя: пройди пальцем по блок-схеме для случая «X1 = 3, пришло X2 = 10» — должно получиться Y2 = M + 13 со стробом.

## Шаг 7. Написать и сдать три программы (КМ-3, часть 2)

Каждая программа — это одна блок-схема из шага 5, переписанная командами, вставленная в шаблон робота (рис. 6 ТЗ). Начинай с первой: без неё КМ-3 не зачтут.

1. **Поставь симулятор** 8051 (Keil µVision или MCU 8051 IDE) — там видно регистры, память и ножки.
2. **Скопируй шаблон** с рис. 6 ТЗ: первая строка — ФИО, группа, вариант, версия; заглушки `nop` / `reti` на всех векторах.
3. **Объяви константы** через EQU: адреса устройств, «голова», «хвост», биты флагов, загрузки таймеров. Потом менять их проще в одном месте.
4. **Инициализация** — только то, что нужно этой программе (стек, ножки, переменные, таймер, прерывания).
5. **Процедура** — переведи блок-схему команда за командой. Над процедурой многострочный комментарий: что делает, что на входе, что на выходе.
6. **Вызов** `call ИмяПроцедуры ; %proc%` — после инициализации или в векторе прерывания (для клавиатуры — в векторе её INT).

8. **Комментарии** — по смыслу («сдвигаем хвост на следующий отсчёт»), а не перевод команды («увеличиваем DPTR»). Не длиннее 250 символов, метки не длиннее 60.

11. **Сохрани** как .txt в UTF-8: «Фамилия ИО-код-1.txt», «-код-2», «-код-3». Отправь с темой «МПС-код», в письме группа и вариант.

Проверка себя: в каждом файле ровно одна строка с %proc% и одна с %stop%, в процедуре нет бесконечных циклов, все неиспользуемые векторы — nop + reti.

## Параметры варианта

Всё задаётся двумя числами: группой и M (1–30). Бит строба Y1: k = M mod 7, строб Y2 — бит k+1 (при M mod 7 = 6 это P1.7). Функция Y2 одна на всех: X1≠0 → Y2 = (M + X1 + X2) mod 256, X1 = 0 → Y2 = 0.

Общее для всех групп:

- Клавиатура: M чётное → 4×3 (4 столбца, 3 строки), M нечётное → 3×4.
- Таймер T3 всегда тот же, что у Y1: пока идёт строб «Теста», индикатор погашен, поэтому таймер свободен. Строб Y2 всегда на втором таймере.

- Тип индикатора (общий катод FYS-5612AX или общий анод FYS-5612BX) — по табл. 1 ТЗ для своей группы. От него зависит, какой уровень зажигает сегмент, а значит и вся таблица кодов символов.

Пример, А-12, M = 14: k = 0, T1 = 352 мс, V = 1540, флаги — биты 26 / 14, T2 = 1745 мкс, индикатор на P2.7, T3 = 2,830 с, клавиатура 4×3 на P2.6 и INT0.

## Производные параметры

Адреса, биты и перезагрузки таймеров считаются из таблицы выше по одним и тем же правилам для любого варианта.

### Адреса устройств

Все CS сидят на P2.3–P2.7 и активны нулём. Буфер при V ≤ 1790 занимает 11 адресных линий (A0–A10, то есть P0 + P2.0–P2.2), поэтому старший байт адреса устройства = F8h со сброшенным битом его CS, а неиспользуемые CS-линии держим в единице.

| CS на линии | Старший байт | Базовый адрес |
| --- | --- | --- |
| P2.7 | 78h | 7800h |
| P2.6 | B8h | 0B800h |
| P2.5 | D8h | 0D800h |
| P2.4 | E8h | 0E800h |
| P2.3 | F0h | 0F000h |

Буфер занимает {BUF} … {BUF}+V−1; адрес {BUF}+V — точка «заворота» указателя обратно на {BUF}. Для индикатора, клавиатуры и Y2 годится любой адрес в их окне, в коде берём базовый. Карту памяти в ПЗ1 рисуем этими же окнами по 2 Кбайт.

### Указатели и флаги

- «Голова» и «хвост» — по 2 байта (V > 256 у всех), храним абсолютный адрес ячейки: младший байт по заданному адресу, старший — следующим. Так их можно сразу грузить в DPTR.
- Бит с адресом b лежит в байте 20h + b div 8, разряд b mod 8. Пример: бит 26 = 23h.2, бит 14 = 21h.6.
- Стек стартует с SP = 07h и растёт вверх. До бит-области (20h) у него 24 байта; глубже — стек затрёт флаги. Это и есть ограничение для ответа про «максимальную глубину стека».

### Таймеры (кварц 12 МГц → машинный цикл 1 мкс)

- Оба таймера в режиме 1 (16 бит): TMOD = 11h.
- Строб Y2: T2 ≤ 2405 мкс помещается в один отсчёт, загрузка TH:TL = 65536 − T2. Пример: T2 = 1745 → 0F92Fh.
- Y1 и T3 длиннее 65 мс, поэтому таймер тикает с периодом {tick} и программа считает тики. Универсальный вариант: tick = 1 мс (загрузка 0FC18h), счётчик 16-битный, T1 и T3 в мс — целые числа при любом M. Можно взять тик крупнее, если T1 и T3 твоего варианта на него делятся.
- Перезагрузку в режиме 1 делаем в обработчике; задержка входа в прерывание даёт несколько мкс ошибки на тик, это стоит одной фразой отметить в ПЗ2.

Если на схеме стоит не 12 МГц, все загрузки пересчитываются: цикл = 12 / f\_кварца мкс.

Первая программа одна у всех, вторая зависит от чётности M, третья — от M mod 3. Каждая сдаётся отдельным файлом «Фамилия ИО-код-n.txt» по шаблону робота (заглушки nop/reti, `call ...; %proc%`, `jmp $; %stop%`).

| № | Условие | Что пишем | Где вызов %proc% |

Ниже — готовые формулировки под каждый раздел шаблона; плейсхолдеры заменяешь значениями своего варианта. Разделы 1–2 — постановка задачи, 3 — как сделано, 4–5 — как этим пользоваться.

**Аннотация.** В данном документе приведено описание программы «Программа управления объектом», предназначенной для управления объектом микропроцессорной системой на базе МК AT89S53: ввода данных с клавиатуры и от внешнего устройства, формирования управляющих сигналов Y1, Y2 и вывода информации на индикатор. **2. Функциональное назначение.**

- 2.1 Классы задач — список из шаблона оставляем как есть.

- 2.3 Ограничения: AT89S53, кварц {f} МГц; X2 — 8 бит параллельно со стробом, до 5 отсчётов/с; Y2 — 8 бит параллельно со стробом низкого уровня {T2} мкс на P1.{k+1}; Y1 — строб низкого уровня {T1} мс на P1.{k}; клавиатура {4×3 | 3×4}, одна позиция индикатора, статическая индикация.

**Перечень сокращений.** МК, МПС, ОЗУ, ПЗУ, ЕСПД, ЕСКД, IRQ, ISR, CS, SP, DPTR — по мере использования.

## Алгоритмы подпрограмм

Каждый пункт ниже — готовая основа для блок-схемы по ГОСТ 19.701 и её пояснения в разделе 3.1. Обозначения: {KB}, {IND}, {Y2R}, {BUF} — адреса устройств, {INTkb} — прерывание клавиатуры, {INTx2} — прерывание строба X2, {TA} — таймер Y1/T3, {TB} — таймер Y2.

### Инициализация (сразу после Reset)

1. SP = 07h (по ТЗ, это значение после сброса).
2. P1 = 0FFh: стробы Y1 и Y2 в пассивной единице.
3. Переменные: X1 = 0; «голова» = «хвост» = {BUF}; флаг пустоты = 1, переполнения = 0; служебные флаги «идёт строб Y2», «режим таймера {TA}» = 0.
4. Индикатор погасить: записать в {IND} код «выкл» (00h для общего катода, 0FFh для общего анода).
5. Регистр Y2: записать 0 со стробом (пассивное состояние, каждая запись — со стробом).
6. Клавиатура: записать 0 во все Col, чтобы любое нажатие опускало строку и вызывало {INTkb}.
7. TMOD = 11h, таймеры остановлены.
8. Прерывания: IT0 = IT1 = 1 (по спаду); {INTx2} — высокий приоритет (ТЗ требует максимальный для ввода X2), остальные — низкий; разрешить EX0, EX1, ET0, ET1, EA.

### Главный цикл

1. Если X1 ≠ 0, буфер не пуст и строб Y2 не идёт → прочитать X2 из буфера → рассчитать и выдать Y2.
2. Иначе, если последнее выданное Y2 ≠ 0 и строб не идёт → выдать Y2 = 0 (один раз, со стробом), дальше буфер не читаем.
3. Вернуться к п. 1. Остальное (клавиатура, запись в буфер, таймеры) живёт в прерываниях.

### Обработчик клавиатуры ({INTkb}) — программа 1

1. Сохранить в стеке ACC, PSW, DPL, DPH.
2. Для каждого столбца i: записать в {KB} маску с нулём только в бите i; прочитать {KB}; оставить биты строк (07h для 4×3, 0Fh для 3×4).
3. Если строки не все единицы: проверить, что ноль ровно в одном бите, и что клавиша ещё не найдена в другом столбце; иначе результат 0FFh.
4. Записать 0 во все Col (вернуть клавиатуру в режим ожидания IRQ).
5. По (столбец, строка) взять код из таблицы 3 ТЗ (movc) → A. Нет нажатия или их несколько → A = 0FFh.
6. Реакция на код: 0–9 → X1 = код, вывести цифру на T3; 10 «Тест» → погасить индикатор, запустить Y1; 11 «Сброс» → очистить буфер, погасить индикатор; любое нажатие гасит висящую ошибку.
7. Восстановить регистры, reti.

### Запись в буфер ({INTx2}) — программа 2 при нечётном M

1. DPTR ← «голова»; записать байт в ячейку (movx @DPTR, A). В схеме, где правый порт пишется по WR МК, именно этот цикл записи фиксирует X2 с разъёма.
2. «Голова» + 1; если = {BUF}+V → «голова» = {BUF}.
3. Если «голова» = «хвост» (догнала) → буфер полон: флаг переполнения = 1, «хвост» + 1 с заворотом (старейший отсчёт теряется).
4. Флаг пустоты = 0.

При такой политике в буфере одновременно живёт до V−1 отсчётов — стоит одной фразой отметить в ПЗ2.

### Чтение из буфера — программа 2 при чётном M

1. Запретить {INTx2} (критическая секция: обработчик тоже двигает указатели и флаги).
2. Если флаг пустоты = 1 → C = 1 («нет данных»), разрешить прерывание, выйти.
3. DPTR ← «хвост»; movx A, @DPTR.
4. «Хвост» + 1 с заворотом; флаг переполнения = 0 (после чтения буфер не полон).
5. Если «хвост» = «голова» → флаг пустоты = 1.
6. C = 0, разрешить {INTx2}, выйти. Результат — в A.

### Очистка буфера (клавиша «Сброс»)

Запретить {INTx2} → «хвост» = «голова» → пустота = 1, переполнение = 0 → разрешить {INTx2}.

### Вывод на индикатор + T3 — программа 3 при M mod 3 = 0

1. Код ≤ 10 → код сегментов из таблицы (movc A, @A+DPTR); иначе код «выкл». Для ошибки — добавить бит dp. Для общего анода — инвертировать (cpl A).
2. Записать в {IND}.
3. Если символ не «выкл»: режим {TA} = «индикация», счётчик = T3 / tick, загрузить и запустить {TA}.
4. Обработчик {TA}: перезагрузка; счётчик − 1; дошёл до 0 → записать «выкл», остановить таймер.

### Строб Y1 — программа 3 при M mod 3 = 1

1. Строб уже идёт → выйти.
2. Погасить индикатор (таймер {TA} забираем у индикации).
3. P1.k = 0; режим {TA} = «Y1», счётчик = T1 / tick; запустить {TA}.
4. Обработчик {TA}: перезагрузка; счётчик − 1; дошёл до 0 → P1.k = 1, остановить таймер.

### Расчёт и выдача Y2 — программа 3 при M mod 3 = 2

1. X1 = 0 → Y2 = 0; иначе A = M + X1 + X2 (8-битное сложение, перенос отбрасывается — это и есть mod 256).
2. Записать Y2 в {Y2R} (movx).
3. P1.(k+1) = 0; флаг «идёт строб Y2» = 1; TH:TL {TB} = 65536 − T2; запустить {TB}.
4. Обработчик {TB}: P1.(k+1) = 1, остановить {TB}, флаг = 0.

## Коды ошибок и ответы на п. 2.3

Таблицу ошибок ТЗ оставляет на твой выбор; ниже заготовка, которую достаточно сократить под свою логику. Ошибка — цифра с горящей dp, висит до любого нажатия, но не дольше T3.

| Индикация | Смысл | Когда выставляется |
| --- | --- | --- |
| 1. | Нажато несколько клавиш | скан вернул больше одного нуля |
| 2. | Нажатие не распознано | IRQ пришёл, а при скане все строки в единице |
| 3. | Переполнение буфера | запись X2 затёрла непрочитанный отсчёт |
| 4. | Повторный «Тест» | нажат «Тест», пока идёт строб Y1 |

### Минимальное время заполнения буфера (X1 = 0)

При X1 = 0 буфер не читается, а X2 приходит не чаще 5 отсчётов в секунду, поэтому:

```latex
t_{min} = \frac{V}{f_{X2}} = \frac{V}{5\ \text{с}^{-1}}
```

Пример: V = 1540 → 308 с. Если по твоей политике в буфере живёт V−1 отсчётов, переполнение наступает на (V−1)/5 с — укажи, какой вариант считаешь.

### Максимальная глубина стека

Худший случай — все уровни вложенности сработали одновременно: главный цикл сидит в подпрограмме, её прервал низкоприоритетный обработчик, а его — высокоприоритетный. Каждый call или вход в прерывание кладёт 2 байта, каждый push — 1.

```latex
D_{max} = D_{main} + (2 + P_{low} + C_{low}) + (2 + P_{high} + C_{high})
```

P — число push в обработчике, C — байты вложенных call внутри него. Ориентир: 2 + (2 + 4 + 2) + (2 + 4) = 16 байт. Проверяешь, что D\_max ≤ 24 байта: иначе стек от 08h дойдёт до бит-области 20h и затрёт флаги. Для ответа по программе 1 считаешь то же только для обработчика клавиатуры.

## Что обязано быть в ПЗ1

По п. 2.1 и 2.3 ТЗ в ПЗ1 любого варианта должны быть пункты ниже; последние три чаще всего забывают.

- [ ] Структурная и функциональная схемы с описанием блоков и распределением ресурсов (таймеры, INT, CS-линии).
- [ ] Демультиплексирование шины (регистр по ALE) с временной диаграммой цикла чтения/записи МК.
- [ ] Подключение буфера, регистра Y2, индикатора, клавиатуры, питания — схема узла + расчёт номиналов (сегментные резисторы, RC-фильтр клавиш, ток через кнопку).
- [ ] Карта памяти: окна устройств по CS-линиям (см. «Производные параметры»).
- [ ] Перечень элементов, список литературы, даташиты в приложении.
- [ ] Временная диаграмма обмена МК ↔ буфер: тайминги МК поверх времён доступа и записи IDT7005, с выводом «укладывается».
- [ ] Оценка мощности: сумма токов потребления микросхем по даташитам + индикатор в худшем случае (все 8 сегментов) + кнопки, умножить на Vcc; требование к источнику (5 В ±5 %, ток с запасом).
- [ ] Механизм доступа внешнего устройства к буферу: кто выставляет данные и строб, какое прерывание срабатывает, кто и когда двигает указатели, сколько внешнее устройство держит данные.

Типовые придирки: фильтрующие конденсаторы 68 нФ (не пФ), КМОП-серии (74AC/74HC) вместо ТТЛ (74AS/74LS), ГОСТовские УГО и заполненная рамка.
