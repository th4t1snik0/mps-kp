# RULES.md — правила работы с общей памятью

Обязательны для любого ИИ-ассистента (Claude, Cursor, Codex, …) и для людей, которые правят репо.
Репо — общая память группы: ошибка, записанная сюда, уедет в курсовые всех. Поэтому
**сначала доказать, потом записать в журнал, потом менять**.

## 1. Что считается важными участками общей памяти

| Участок | Почему важно |
| --- | --- |
| `AGENTS.md`, `RULES.md`, `CLAUDE.md` | правила, по которым работают все ИИ |
| `docs/research/*.md` | выжимки и чек-листы, на которые ссылаются все |
| `docs/riba.md` | пошаговый гайд курсовой |
| `data/table-*.yaml` | числа вариантов из ТЗ |
| `internal/variant/` | формулы параметров (адреса, биты, таймеры, программы) |
| `internal/schgen/mps.go`, `cmd/mpslib/`, `masters/` | схемотехника листа Э3, символы, выводы |
| раздел «Принятые решения по схеме» в `AGENTS.md` | согласованные решения |
| `notes/*.md` | только дописывать; исправлять чужую запись — тоже по этим правилам |

Не важные (менять свободно): свой `sessions/<дата>-<ник>.md`, свой `students/<ник>/`, `build/`, опечатки
и форматирование, которые не меняют смысл.

## 2. Протокол изменения важного участка

Прежде чем менять, ИИ **обязан**:

1. **Прочитать текущее состояние целиком** — сам участок, связанные записи в `docs/changelog.md`
   (не отменяем ли чужое решение?) и последние файлы `sessions/`.
2. **Доказать изменение.** Доказательство — это ссылка, которую можно проверить:
   - документ: файл + страница/раздел + короткая цитата (ТЗ и методичка в `docs/source/`, лекции,
     даташиты, принятые работы в `docs/prev/`, `docs/group/`);
   - проверка: тест (`make test`), netlist/ERC (`build/*/erc-summary.txt`), рендер PNG, расчёт с формулой;
   - слова руководителя — только с записью в `notes/remarks.md` (дата, кто слышал).
   «Я знаю, что так правильно» и «так обычно делают» — не доказательство.
3. **Перепроверить дважды** (см. раздел 3).
4. **Записать в журнал** `docs/changelog.md` **до или вместе** с изменением, в том же коммите, по шаблону
   из журнала: было → стало, почему, доказательства, как проверено, что затронуто.
5. **Если меняется согласованное решение** (есть в «Принятых решениях» или в журнале с пометкой
   «подтвердил человек») — не менять самому: описать предложение в своей сессии и спросить человека.
   Менять после его «да», в журнале указать, кто подтвердил.
6. **Если доказать не получилось** — не менять. Записать вопрос в `sessions/<дата>-<ник>.md`
   в раздел «Открытые вопросы» с тем, что уже найдено.

## 3. Двойная проверка перед любым утверждением

Касается не только правок, но и ответов людям («у нас в схеме так-то», «в ТЗ сказано…»).

1. **Первая проверка — по источнику.** Открыть источник заново в этой сессии (не по памяти, не по
   старой выжимке) и найти место. Числа варианта — только из генератора (`make try`).
2. **Вторая проверка — независимая.** Другой источник (ТЗ ↔ методичка ↔ лекция ↔ даташит ↔ принятая работа),
   или машинная проверка (тест, netlist, ERC, рендер), или пересчёт другим способом.
3. **Расхождение** между источниками — не выбирать молча: назвать оба, указать, чей приоритет
   (ТЗ текущего года > методичка > лекции > даташит > работы прошлых лет > форумы/память ИИ) и почему.
4. **Не удалось проверить дважды** — так и сказать: «не проверено: …». Не выдавать догадку за факт.
5. **Работы прошлых лет** — сверять с ТЗ текущего года: задания менялись (см. `docs/research/remarks-and-defense.md`, раздел D).

## 4. Актуальность контекста

- **В начале сессии:** `AGENTS.md`, этот файл, последние 5–10 записей `docs/changelog.md`,
  последние 2–3 файла `sessions/`, `README.md` («Статус»). Если вопрос про схему или требования —
  соответствующий файл `docs/research/`.
- **Перед ответом по теме — смотреть первоисточники,** а не только выжимки: ТЗ и методичку (`docs/source/`),
  лекции (`docs/prev/mailru-mps-course/Лекции/`, если скачаны; ссылки — `docs/materials.md`),
  даташиты (`docs/group/`), принятые примеры. Выжимка может устареть или содержать ошибку.
- **Нашёл устаревшее или ошибку** в общей памяти — исправить по протоколу из раздела 2
  (или записать открытым вопросом, если доказать не получается).
- **Новые материалы** (новое ТЗ, замечание руководителя, вопросы с защиты, чужая принятая работа) —
  сразу разложить: сырьё в `docs/prev/` или `docs/source/`, выжимку в `docs/research/`, факт в `notes/`,
  запись в журнал, если это меняет важный участок.
- **В конце заметной сессии** — дописать `sessions/<дата>-<ник>.md`: что сделано, что решили (со ссылкой
  на записи журнала), что дальше, открытые вопросы.

## 5. Git

- `main` не защищён — поэтому дисциплина на нас. Мелкое и своё — можно сразу в `main`.
  Важные участки — отдельным коммитом, в сообщении ссылка на запись журнала (`changelog: 2026-09-30/03`).
- Перед пушем: `make test`; если трогал схему — `make try` на 3–4 вариантах, пустой ERC, PNG глазами.
- Не переписывать историю (`push --force`, `rebase` опубликованного) — другие уже могли стянуть.
- Не коммитить: `docs/prev/`, `build/`, `CLAUDE.local.md`, секреты.
