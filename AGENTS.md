# AGENTS.md — правила для ИИ-ассистентов (и людей) в этом репо

Общая база группы по курсовой «Микропроцессорные системы ч.2» (НИУ МЭИ, ИВТИ, кафедра ВМСС,
руководитель — Михалин С.Н.): генератор материалов под вариант + выжимки из работ прошлых лет
+ общая память ИИ-сессий. Работают несколько человек и несколько ИИ (Claude Code, Cursor, Codex…).

> **Обязательно:** [`RULES.md`](RULES.md) — как менять общую память (доказать → записать в
> [`docs/changelog.md`](docs/changelog.md) → изменить) и двойная проверка перед любым утверждением.

**Каждая сессия начинается с:** этот файл, `RULES.md`, последние записи `docs/changelog.md`,
последние 2–3 файла `sessions/`, `README.md` («Статус»); по теме — `docs/research/*.md` и первоисточники.

## Главные правила

1. **Числа варианта не считать в уме.** Всё (CS, адреса, биты, таймеры, какие программы писать)
   считает генератор: `make try G=<группа> M=<номер>` → `build/try-<группа>-<M>/params.md`.
2. **Схему Э3 не рисовать руками с нуля** — её строит `internal/schgen`. Если что-то не так в схеме —
   правь код построителя (для всех), а не свой `.kicad_sch` (только для себя; допустимо, но отметь в сессии).
3. **Правила ТЗ важнее примеров прошлых лет.** ТЗ и методичка — `docs/source/`. Работы прошлых лет
   делались по другому заданию (АЦП, UART, 2 разряда индикатора и т.п.) — см. `docs/research/remarks-and-defense.md`, раздел D.
4. **Не выдумывай факты про кафедру.** Требования и замечания руководителя — только из `docs/`, `notes/`
   и `sessions/` с источником. Нет источника — так и скажи.
5. **Пиши по-русски.** Для людей: связно и по шагам, без воды.

## Генератор

```sh
make test                        # go test ./... (netlist-тест схемы требует kicad-cli, без него пропускается)
make try G=А-12 M=14             # любой вариант → build/try-А-12-14/
make student S=<ник>             # из students/<ник>/variant.yaml → build/<ник>/
make lib                         # пересобрать masters/lib/mps.kicad_sym (только при правке cmd/mpslib)
scripts/render.sh build/<папка>  # только PDF/PNG/ERC по готовому .kicad_sch
```

Нужно: Go 1.23+, KiCad 10 (`kicad-cli`), poppler (`pdftoppm`), шрифт GOST type A (`fonts/` — поставить в систему).
macOS: `brew install --cask kicad && brew install go poppler`. Ubuntu: PPA `ppa:kicad/kicad-10.0-releases`.
Без установки: GitHub → Actions → build → Run workflow (группа + M) → сводка на странице запуска
(картинка, ERC, параметры). Всё, что сделала джоба, — в ветке `results` (`results/<папка>/…`, оглавление в её README).
Ветку `results` пишет только CI (`scripts/publish.sh`), руками не править.

Что получается в `build/<папка>/`: `params.md` (все параметры варианта и ответы на п. 2.3 ТЗ), `params.json`,
`vars.inc` (EQU/BIT для асма), `schematic.kicad_sch` (открывается в KiCad 10), `schematic.pdf/png`,
`erc-summary.txt` (**должен быть пустым**).

**Таблица вариантов сейчас от ТЗ-2025** (прошлый год). Когда выдадут новое ТЗ — `data/table-<год>.yaml`
+ сверить `docs/research/` с новым текстом.

## Устройство кода

- `data/table-2025.yaml` — табл. 1 ТЗ. `internal/variant` — расчёт параметров (k = M mod 7 и т.п.).
  Эталон: А-12, M=14. Любое изменение формул — сначала тест.
- `internal/schgen` — построитель схемы Э3:
  - `mps.go` — раскладка листа по образцу принятой схемы (Рязанцев, А-12-22, 2025, `docs/source/старая-схема-Э3.png`),
    вариант подставляется кодом: CS/INT/стробы на выводах МК, клавиатура 4×3/3×4, индикатор ОК/ОА;
  - `sheet.go` — примитивы KiCad (символы, провода, шины, метки, автоточки, разрезание проводов на выводах);
  - `renumber.go` — позиционные обозначения по ГОСТ 2.710 (сверху вниз, столбцами слева направо);
  - `netlist_test.go` — сверяет состав цепей через `kicad-cli` (ловит слияния цепей и КЗ, которые ERC не видит);
  - роли элементов (`b.role("mcu", …)`) — по ним пишется «Примечание» и проверяются цепи.
- `cmd/mpslib` — собирает `masters/lib/mps.kicad_sym` из библиотек KiCad (+ IDT7005, FYS-5612, ГОСТ-земля).
- `internal/render` — `params.md`, `vars.inc`. `masters/gost_ramka.kicad_wks` — рамка ГОСТ.

**Проверка правок схемы:** `make test` → `make try` на 3–4 вариантах (чётный/нечётный M, INT0/INT1) →
`erc-summary.txt` пустой → **посмотреть PNG глазами** (наложения надписей и провода сквозь символы тесты не ловят).

## Принятые решения по схеме (не менять без обсуждения)

Подробно и с источниками — `docs/research/schematics-review.md`. Кратко:
RC-сброс 10 мк/10 к; EA→+5 В, PSEN не подключён; только КМОП (74HC/AC, 1554); 68 н на каждый корпус + 470 мк;
IDT7005 в режиме slave (M/S→GND, BUSY→+5 В); Load 573 = ИЛИ-НЕ(CS, WR); OE 244 = ИЛИ(CS, RD); Cp 173 ← WR;
MR 173 ← RST; клавиатура: подтяжка 2 к + 10 к + 220 н (3RC ≥ 5 мс), триггер Шмитта не ставим;
номиналы по ГОСТ 2.702 («10 к», «68 н»).

Открытые вопросы — в конце `README.md` (раздел «Статус»).
