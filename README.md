# МПС ч.2 — курсовая и генератор под вариант

Общая база группы по курсовой «Разработка микропроцессорной системы на базе МК i8051»
(«Микропроцессорные системы ч.2», НИУ МЭИ, ИВТИ, кафедра ВМСС).

Вводишь группу и номер варианта M — получаешь:
- все параметры варианта (выводы, карта памяти, флаги, таймеры, какие 3 программы писать, ответы на п. 2.3 ТЗ);
- `vars.inc` — EQU/BIT для ассемблера;
- **схему Э3 на А3 с рамкой ГОСТ** (KiCad 10 + PDF + PNG), собранную под твой вариант: CS, INT и стробы
  на нужных выводах, клавиатура 4×3 или 3×4. ERC чистый, цепи проверены тестом.

> Всё по **ТЗ-2026** (`docs/source/ТЗ-2026.pdf`, выдано осенью 2026): группы А-06, А-07, А-08, А-09, А-12, А-17, Аэ-21;
> CS — с дешифратора 74HC138. Что поменялось против 2025 — `docs/research/tz-2026.md`.
> Прошлогодняя таблица оставлена: `make try TABLE=data/table-2025.yaml …`.

## Для студентов

**Всё делается через Issue — ничего ставить не нужно, права на запись в репо тоже.**

1. Вкладка **Issues → New issue → «Мой курсач»**: ФИО («Фамилия И.О.»), группа, вариант, преподаватель, стиль листа → создать.
2. Бот ответит в Issue: заведёт вашу папку `students/<ник>/` и соберёт **схему Э3 и перечень (КМ-1)** — придёт комментарий
   с картинкой, PDF и ссылкой на **вашу папку на Яндекс-диске** (`MPS-SHEMAS/<группа>/<M> <Фамилия И.О.>/СХЕМА-N/`).
3. Дальше — команды комментариями (полный список — `/помощь`):
   - `/заготовки` — заготовки программ, ПЗ1, ПЗ2 и схем алгоритмов под ваш вариант;
   - `/пз1` + блок с текстом — **ПЗ1 (КМ-2)**;
   - `/prog1` + блок с кодом (и `/prog2`, `/prog3`) — проверка программ, файлы для робота и **ПЗ2 (КМ-3)**; `/пз2` + блок — текст ПЗ2;
   - `/замечание КМ-1 текст` — записать замечание руководителя; `/правка` + блок yaml — поправить схему по нему;
   - `/файл <путь>` + блок, `/удалить <путь>` — любой файл своей папки (`.a51`, `.md`, `.flow`, `.yaml`);
   - `/всё` — пересобрать схему, затем ПЗ1 и ПЗ2 по ней;
   - `/доступ` — попросить права на запись в репо (работать пушами без Issue).
4. Каждый прогон — новая папка (`СХЕМА-N`, `ПЗ1-K по СХЕМА-N`, `ПЗ2-K по СХЕМА-N`), старые не пропадают. ПЗ — в docx
   (дописать «ДОПИШИ», сохранить в PDF самому) и «— просмотр.pdf», чтобы посмотреть.

С нейронкой: дайте ей ссылку на этот репо и на ваш Issue — пусть читает `AGENTS.md` и шлёт файлы командами выше.
Просто посмотреть схему любого варианта: Actions → **Проба варианта** (для участников репо).

## Для ИИ

Начинай с [AGENTS.md](AGENTS.md) (там сценарий «Курсач под ключ» и «Замечания руководителя») и [RULES.md](RULES.md).
Коротко:

- **Один источник данных студента** — `students/<ник>/variant.yaml`; ник считает `make nick G=А-12 FIO="Рязанцев И.В."`.
- **Порядок:** КМ-1 (схема `СХЕМА-N`) → КМ-2 (ПЗ1) и КМ-3 (программы + ПЗ2) берут **сданную** `СХЕМА-N`, а не строят свою.
- **Без прав на запись** — всё через Issue студента командами (`/prog1` + блок, `/пз1` + блок, `/правка` + yaml, `/файл <путь>` + блок,
  `/удалить <путь>`, `/замечание …`; список — `/помощь`); права на запись — `/доступ` (решает владелец репо);
  файлы студента читай в репо (`students/<ник>/`), готовое — в ветке [results](../../tree/results) и в комментариях бота.
- **С правами** — правь `students/<ник>/` и пушь: джобы пересоберут только этого студента.
- **Локально** (Go 1.23+, для схемы — KiCad 10, для ПЗ — pandoc):

```sh
make try G=А-12 M=14 FIO="Рязанцев И.В."   # параметры + схема варианта → build/А-12-23/14/
make student S=<ник>                        # то же из students/<ник>/variant.yaml
make code-init S=<ник> && make code S=<ник> # заготовки программ и проверка (эмулятор 8051)
make pz1 S=<ник> / make pz2 S=<ник>         # ПЗ в docx
make remark S=<ник> KM=1 TEXT="…"           # замечание руководителя → students/<ник>/remarks.md
```

Как писать программы — [`docs/code-guide.md`](docs/code-guide.md), ПЗ — [`docs/pz-guide.md`](docs/pz-guide.md),
правки схемы по замечаниям (`schema/fixes.yaml`) — AGENTS.md. Настройка репо (Яндекс-диск, Issue-бот) — [`docs/admin.md`](docs/admin.md).

## Правила для ИИ в этом репо

Правила для ИИ-ассистентов — в [AGENTS.md](AGENTS.md) и [RULES.md](RULES.md): важное в общей памяти
меняется только с доказательством и записью в [журнал](docs/changelog.md), любое утверждение проверяется дважды
(Claude Code читает AGENTS.md через `CLAUDE.md`, Cursor/Codex — напрямую). Коротко: числа варианта считает генератор,
итоги сессии — в `sessions/`, замечания и вопросы — в `notes/`, выжимки — в `docs/research/`.
Свои предпочтения («объясняй проще», «я знаю C») — в `CLAUDE.local.md`, он не коммитится.
